# Week-of Date Bug Analysis

## Symptom

Challenges generated by the backfill script have `weekOf` dates that are **not 7 days apart** and **not on Mondays**:

| Challenge | weekOf | Day | Gap |
|---|---|---|---|
| Yoga Pose (w16) | 2026-04-13 | Mon | — |
| Alphabet (w15) | 2026-04-09 | **Thu** | **4 days** |
| Passing Phone (w14) | 2026-04-03 | **Fri** | **6 days** |
| Color Hunt (w13) | 2026-03-28 | **Sat** | **6 days** |
| Temperature (w12) | 2026-03-16 | Mon | **12 days** |

The original hand-entered challenges (w03–w10) are all correctly on Mondays, 7 days apart.

## Root Cause

The `addDays()` function in `scripts/generate-challenge.mjs` has a **timezone bug**:

```js
function addDays(dateStr, days) {
  const date = new Date(dateStr + 'T00:00:00'); // local time (e.g. UTC+9)
  date.setDate(date.getDate() + days);
  return date.toISOString().split('T')[0]; // converts to UTC → shifts date back
}
```

**What happens step by step:**

1. `new Date('2026-03-16T00:00:00')` → creates March 16 at **midnight local time** (UTC+9)
2. In UTC, that's `2026-03-15T15:00:00Z` — still March **15** in UTC
3. `.setDate(date.getDate() + 7)` → adds 7 to the **local** date (16 → 23), giving March 23 at midnight local
4. `.toISOString()` → converts back to UTC → `2026-03-22T15:00:00Z`
5. `.split('T')[0]` → returns `"2026-03-22"` — a **Sunday**, not the Monday (March 23) we wanted

Each successive `addDays` call compounds the drift because the starting date is already wrong (Sunday instead of Monday), and the cycle repeats — drifting backwards one day per iteration relative to the expected Monday.

The same bug exists in `getNextMonday()`:

```js
function getNextMonday() {
  const now = new Date();
  const day = now.getDay(); // local day-of-week
  // ... calculates correct local Monday ...
  return nextMonday.toISOString().split('T')[0]; // UTC conversion shifts it back
}
```

This one *happens* to produce the correct date in most cases because `now` includes the current time (not midnight), but it's still fundamentally fragile.

## Fix

Replace `.toISOString().split('T')[0]` with a **local-time** date formatter that avoids the UTC conversion entirely:

```js
function formatDateLocal(date) {
  const y = date.getFullYear();
  const m = String(date.getMonth() + 1).padStart(2, '0');
  const d = String(date.getDate()).padStart(2, '0');
  return `${y}-${m}-${d}`;
}
```

Apply this to both `addDays()` and `getNextMonday()`.

## Corrected Dates

All `weekOf` values should be Mondays, 7 days apart:

| id | Old weekOf | Corrected weekOf |
|---|---|---|
| 2026-w16 | 2026-04-13 | 2026-04-13 (correct) |
| 2026-w15 | 2026-04-09 | 2026-04-06 |
| 2026-w14 | 2026-04-03 | 2026-03-30 |
| 2026-w13 | 2026-03-28 | 2026-03-23 |
| 2026-w12 | 2026-03-16 | 2026-03-16 (correct) |
| 2026-w10 | 2026-03-03 | 2026-03-03 (correct, but gap to w12 = 13 days → w11 is missing) |

Note: w11 (2026-03-09) was never generated — this is a separate gap, not caused by this bug.
